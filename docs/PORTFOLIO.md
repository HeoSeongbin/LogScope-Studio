# LogScope Studio 포트폴리오 소개

LogScope Studio는 Spring/.NET/JSON/IIS 등 서로 다른 로그를 브라우저에서 읽고 같은 이벤트 모델로 탐색하는 로컬 분석 도구다. 여러 줄 예외와 원본 위치를 보존하고, 반복 예외·UTC 통계·명시적 요청 식별자로 관측 흐름을 확인한다. 로그 원문을 서버나 브라우저 영구 저장소로 자동 전송/저장하지 않는다.

## 해결한 기술 문제

1. 혼합 형식과 손상 입력: 파일의 첫 형식을 전체에 강제하지 않고 행별 파싱과 JSON 문서 우선순위를 결합했다. 미해석 행도 원문·위치·원인 진단으로 남긴다.
2. 여러 줄 예외의 경계: Java/.NET 원인/억제 구조를 분석하되 새 헤더·빈 줄·일반 텍스트에서 병합을 멈춘다. 생략된 프레임이나 누락 시각은 복원하지 않는다.
3. 청크에 따른 결과 변동: UTF-8/UTF-16 디코딩·CRLF·ILogger 다음 메시지·JSON 배열·스택 상태를 유지하고 1바이트 청크까지 동기 기준 결과와 비교했다.
4. 시간/ID의 과도한 추론: 실제 오프셋을 우선하며 사용자 시간대 가정에는 근거를 남긴다. DST 모호/누락을 거절하고 서로 다른 ID 타입·연결 범위·Span Trace 문맥을 구분한다. 관측 순서를 인과관계로 확정하지 않는다.
5. 브라우저 응답성과 자원 수명: 파싱 Worker 직렬 큐·취소/제한 시간·작업 토큰을 사용하고 큰 원본은 Blob으로 분리한다. 늦은 응답이 제거/초기화 후 결과를 되살리지 않게 했다. 임의 정규식도 종료 가능한 별도 Worker에서 실행한다.
6. 내보내기 정확성과 표시 안전성: JSON 원문 필드와 CSV 표시 방어를 구분하고 HTML을 이스케이프한다. 범위/파일/선택이 바뀌면 이전 다운로드를 취소한다.

## 검증의 경계

수치·벤치마크·배포 상태는 PROGRESS.md, TEST-CASES.md, PERFORMANCE.md와 측정 JSON을 기준으로 한다. 합성 로그의 측정값을 실제 서비스 전체 성능으로 일반화하지 않는다. 자동 axe가 통과해도 전체 접근성 적합성·실기기/스크린리더 검증과 구분한다. CSV 수식 방어는 스프레드시트 재저장 후까지 보장하지 않으며 정확한 데이터 재사용에는 JSON을 안내한다.

파일별 시간대/서비스 설정은 사용자 가정이다. Request/Trace ID가 같아도 로그 누락·ID 재사용·서버 시계 차이가 있을 수 있다. 로컬 메모리 한도와 대표 입력 성능 검증은 무제한 처리 보장이 아니다.
