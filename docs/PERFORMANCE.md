# Phase 7 성능 측정

2026-11-12, Windows x64, Node v24.12.0, AMD Ryzen AI 7 350. `node scripts/benchmark.mjs`는 Vite로 프로덕션 파싱 Worker를 빌드한 후 크기별 별도 Node 프로세스/worker_threads에서 실행한다. 약 1 KiB Spring 합성 행을 반복하며 완전한 행 수만 생성한다. 사용자 로그를 사용하거나 외부로 보내지 않는다. 각 크기 1회 실행이며 통계적 분포나 브라우저 실측이 아니다.

|목표 크기|실제 바이트|이벤트|Worker 내부 파싱|시작·전달 포함|프로세스 최대 RSS|10ms heartbeat 최대 간격|
|---|---:|---:|---:|---:|---:|---:|
|1 MiB|1,048,575|1,023|16.3 ms|64.9 ms|77.0 MiB|18.8 ms|
|10 MiB|10,485,750|10,230|107.7 ms|192.3 ms|157.1 MiB|33.3 ms|
|50 MiB|52,428,750|51,150|455.2 ms|697.8 ms|491.4 MiB|111.8 ms|

파싱 실패는 모두 0이며 생성 행 수와 결과 이벤트 수가 일치한다. 원시 소수점 수치와 환경은 benchmarks/phase7.json에 보존했다. RSS는 메인/Worker/합성 원본/결과 메시지 복제까지 포함한 프로세스 값으로, 10ms 샘플 및 최종 결과 수신 시 값의 최대다. 순간 피크를 놓칠 수 있다. Worker 내부 시간에는 메인 결과 복제 비용이 포함되지 않는다. heartbeat는 브라우저 FPS나 UI 입력 지연 측정이 아니다. 50 MiB 결과 전달은 메인 응답 간격을 약 112ms로 늘렸고 완전한 무정지 처리를 보장하지 않는다.

초기 추정 보관량 512 MiB는 이 50 MiB 입력의 계산치 570,629,400 바이트를 거절했다. 최종 파일별 한도는 640 MiB, 세션은 768 MiB로 설정했다. 추정식은 이벤트당 1024 + rawText 문자수×8 + message 문자수×2 + 예외 프레임수×256이다. 실제 heap 상한을 보장하지 않으며 구조화 필드/예외 트리/문자열 표현/메시지 복제/GC/집계 색인에 따라 달라진다. 짧은 행이나 복잡한 구조화 로그는 50 MiB 전에 이벤트/보관량/레코드 제한으로 거절될 수 있다.

파일 50 MiB, 원본 세션 64 MiB, 이벤트 파일 200,000/세션 250,000개, 행 1 Mi 문자, 레코드/연속 스택 2 Mi 문자 제한을 함께 적용한다. 제한 초과 결과를 일부만 완료 처리하지 않는다. 원본은 제거/초기화까지 재시도용 Blob으로 남고 큰 원본 미리보기는 처음 512 KiB뿐이다. 메모리는 File/Blob을 해제해도 GC 전 즉시 감소한다고 보장하지 않는다.

후속 검증: 실제 브라우저 Worker URL/모듈 로드, UI 취소/응답성, 모바일/저메모리, 대표 실제 로그 분포, 반복/장시간 세션, 다중 파일의 전체 집계·검색. 일반 검색/필터/통계/추적 및 결과 전달은 메인 스레드에 남는다. 이번 측정만으로 이 경로의 대용량 성능을 완료 처리하지 않는다.
